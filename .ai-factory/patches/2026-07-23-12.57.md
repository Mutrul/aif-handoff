# Security audit failed after new transitive dependency advisories

**Date:** 2026-07-23 12:57 MSK
**Files:** `package-lock.json`
**Severity:** high

## Problem

The pull request security workflow began failing at
`npm audit --omit=dev --audit-level=high` even though the feature branch had
not changed dependency manifests or the lockfile.

## Root Cause

Two high-severity advisories for `fast-uri` were published after the last
successful audit on `main`. The existing lockfile resolved the transitive
dependency to vulnerable `fast-uri@3.1.2`, so the same dependency graph became
blocking when npm's advisory database changed.

## Solution

Refreshed the lockfile with the non-breaking, non-force npm audit fix. The
runtime dependency now resolves to patched `fast-uri@3.1.4`; the same refresh
also updated other compatible transitive packages, including `body-parser`.
The exact CI audit command now exits successfully. Remaining moderate
advisories either have no compatible upstream fix or are below the workflow's
configured blocking threshold.

No application logging was added because the fix changes dependency
resolution only and introduces no runtime control flow.

## Prevention

- Treat advisory-database changes as a source of CI drift even when a branch
  does not modify dependencies.
- Prefer a non-force lockfile refresh for compatible transitive security
  patches.
- Never use `npm audit fix --force` when it proposes an incompatible SDK
  downgrade; review the upstream dependency path instead.
- Keep the exact production audit command in CI so newly published high and
  critical advisories remain blocking.
